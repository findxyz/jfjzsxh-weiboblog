# 设计：阅读列宽与字号优化

- 日期：2026-06-21
- 范围：`web/style.css`（仅 CSS，零 JS 改动）
- 目标：宽屏下微博正文太宽不易阅读 → 内容集中到左侧 760px，正文适当放大；转发文字保持原大小。

## 背景

当前布局中 `#post-list` 为 `flex:1`，`.post-card` 为块级元素撑满整个查看区宽度。在宽屏（>960px 查看区）下，单行可达 1500px+，行长过长严重影响阅读。正文字号 14px 偏小。转发引用块文字 13px，层级合适，用户要求保持不变。

## 决策

| 项 | 决策 |
| --- | --- |
| 内容列最大宽度 | 760px |
| 正文字号 | 15px（原 14px） |
| 转发文字字号 | 13px（不变） |
| 内容区对齐 | 左对齐，右侧留白 |
| 顶部日期指示条 | 保持通栏（作为页眉） |

## 方案选型

三种实现方式对比：

- **方式 A（采纳）：`.post-card { max-width: 760px }`**
  - 卡片块级元素默认左对齐，右侧自然留白。
  - `#post-list` 滚动容器保持全宽，滚动条贴视口最右侧，右侧为干净空白区。
  - 改动最小，无需媒体查询即可自适应窄屏。
- **方式 B：`#post-list { max-width: 760px; margin-right: auto }`**
  - 滚动条移到 760px 边界，右侧成为独立死区；观感别扭，不采纳。
- **方式 C：在 `#post-list` 内套 `.post-feed` 包装层**
  - 视觉同 A，但需改 `app.js`（`renderPosts` 直接 append 到 `postList`），无额外好处，不采纳。

## 改动明细

### 1. 内容列宽度

```css
.post-card {
  max-width: 760px;   /* 新增 */
}
```

- 窄屏时 `max-width` 自动让位，行为同现状。

### 2. 正文字号

```css
.post-text {
  font-size: 15px;    /* 14px → 15px */
}
```

- 仅原微博正文 `.post-text` 调整。
- 转发引用块 `.retweet-text` 保持 13px 不变。
- 正文 `line-height: 1.6` 不动。

## 不改的部分

- `.retweet-text` 13px、`.post-meta` 12px、`.post-time`/`.post-link` 12px 等次要信息字号不变。
- 卡片内边距、阴影、左边框、hover、高亮动画等视觉风格不变。
- 侧边栏 200px、顶栏布局、`#day-indicator` 通栏样式不变。
- `web/index.html`、`web/app.js` 不变。

## 验证

1. 启动本地服务，宽屏（≥1200px 视口）打开查看器：
   - 卡片内容收窄到 760px，左对齐，右侧留白。
   - 滚动条仍贴视口最右侧。
   - 正文 15px，转发引用块文字 13px（明显小于正文）。
   - 顶部日期条通栏不变。
2. 窄屏（如 800px 视口）：卡片自适应收缩到视口宽度，行为同现状，不出现横向滚动。
3. 长文微博、含转发原微博、含图片/视频的卡片排版正常，无溢出。
